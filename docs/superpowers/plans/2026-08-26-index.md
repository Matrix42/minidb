## 面向实现的背景速览(对代码库零背景也够用)

MiniDB 三模块(parser / storage / server)分层:

- **minidb-parser** — JavaCC/FMPP 代码生成解析器。配置在 `minidb-parser/src/main/codegen/config.fmpp`(点名 parser 方法名单与 import),语法规则在 `.../codegen/includes/parserImpls.ftl`,token 声明在 `.../codegen/templates/Parser.jj`(已确认 **`<INDEX>` 不是预声明 token,`<UNIQUE>` 是**)。自定义 SqlNode 放 `minidb-parser/src/main/java/com/minidb/parser/ddl/`(现有 `SqlAlterTable` 即范例)。
- **minidb-storage(minidb-common / minidb-arrow / minidb-lsm)** — `TableSchema`(record)在 common;`LSMTable` 在 lsm:构造器 `(TableSchema schema, PartFormat format, BufferAllocator allocator, Path tableDir, long memtableSizeBytes, int bloomBitsPerKey, int l0FileLimit, int levelSizeMultiplier)`;`scan(rangeLo, rangeHi)` 是**超集语义**(文件/块级裁剪,块内行不过滤,注释明说"超集语义,行级过滤由调用方按原条件做"),`getByKey(List<Object> key)` 点查;`decodeKey`/`encodeKey` 只用 Integer/Long/Short/String/null。
- **minidb-server** — `QueryExecutor.handleDdl`(`instanceof SqlDdl` 分支链,新节点插在 throw 前,返回 `QueryResult.Update(0)`);`ConstraintChecker.validateInsert(ctx, schema, target, batch)`;`MiniDbModify`(INSERT=`appendRows`,UPDATE/DELETE=`lsmModify`);`MiniDbScan`(构造器收 `projectedColumns`+`pushedFilter`,`execute()` 先主键点查 `PointLookup.extract` 再主键范围 `RangeBounds.extract` 再全扫,`explainTerms` 输出 explain 项);`MiniDbCalciteTable extends AbstractTable`(已有私有构造 `(TableSchema ts, MiniDbCatalog catalog)`,`AbstractTable.unwrap(Class)` 返回自身——已反编译验证,`RelOptTableImpl.unwrap` 会转发到 table 对象)。
- **catalog 持久化** — `TableSchema` 经 `CatalogSnapshot` → `JsonCatalogStore`(Jackson `ObjectMapper`,record 原生支持;旧 catalog.json 缺新字段时 Jackson 传 null,record canonical 构造器归一即可兼容)。

**行级工具**:`RowVectors`(`readObject`/`writeObject`/`buildRoot`/`materializeToRoot`)与 `RowCopier`(`copyRow`/`copyRows`)在 `com.minidb.server.exec`,用于从数据批提取索引列+主键列构建索引表批。

**测试基建**(`minidb-server/src/test/java/com/minidb/server/exec/`):`PointLookupTest` 模式 = `@TempDir Path dataDir` + `RootAllocator` + `MiniDbCatalog` + `new StorageManager(catalog, allocator, dataDir)` + `StatsManager` + `QueryExecutor` + `ExplainExecutor`;tearDown = `storage.close()` → `allocator.close()`。

**每次提交前跑**:`./mvnw.cmd test -pl minidb-server -am`(全量 `./mvnw.cmd test` 最后跑一次)。TDD:每个任务先写测试(红)→ 实现(绿)→ commit。

## Task 2 — parser:CREATE INDEX / DROP INDEX 语法

**目标**:`CREATE [UNIQUE] INDEX name ON [schema.]t (col, ...)` 与 `DROP INDEX [IF EXISTS] name ON [schema.]t` 可解析成自定义 SqlNode。

### 新文件

`minidb-parser/src/main/java/com/minidb/parser/ddl/SqlCreateIndex.java` — **extends `SqlCreate`**(createStatementParserMethods 的 method 必须返回 SqlCreate):

```java
public class SqlCreateIndex extends SqlCreate {
    private static final SqlOperator OPERATOR =
            new SqlSpecialOperator("CREATE INDEX", SqlKind.OTHER);
    private final boolean unique;
    private final SqlIdentifier indexName;   // SimpleIdentifier
    private final SqlIdentifier table;       // CompoundIdentifier [schema.]t
    private final SqlNodeList columnList;    // SimpleIdentifier 列表

    public SqlCreateIndex(SqlParserPos pos, boolean unique, SqlIdentifier indexName,
                          SqlIdentifier table, SqlNodeList columnList) {
        super(OPERATOR, pos, false);   // 无 replace 语义
        ...
    }
    // getOperandList() 返回 ImmutableNullableList.of(indexName, table, columnList)
    // unparse(): keyword("CREATE") + [unique → "UNIQUE"] + keyword("INDEX") + name
    //            + keyword("ON") + table + columnList.unparse(writer, 1, 1)
    // clone(SqlParserPos) 照抄(参照 SqlAlterTable.clone)
}
```

`minidb-parser/src/main/java/com/minidb/parser/ddl/SqlDropIndex.java` — **extends `SqlDrop`**:

```java
public class SqlDropIndex extends SqlDrop {
    private static final SqlOperator OPERATOR =
            new SqlSpecialOperator("DROP INDEX", SqlKind.OTHER);
    private final boolean ifExists;
    private final SqlIdentifier indexName;
    private final SqlIdentifier table;
    // SqlDrop(SqlOperator, SqlParserPos, boolean ifExists) 是 protected 构造器
    ...
}
```

### 修改文件

`minidb-parser/src/main/codegen/config.fmpp`:

- imports 加 `"com.minidb.parser.ddl.SqlCreateIndex"`、`"com.minidb.parser.ddl.SqlDropIndex"`
- keywords 加 `"INDEX"`;**nonReservedKeywordsToAdd 加 `"INDEX"`**(不保留,可当标识符用)
- createStatementParserMethods 加 `"SqlCreateIndex"`(加在列表末尾)
- dropStatementParserMethods 加 `"SqlDropIndex"`(加在列表末尾)

`minidb-parser/src/main/codegen/includes/parserImpls.ftl`(追加两个 method,仿 `SqlDropTable`/`SqlAlterTable` 结构):

```java
SqlCreate SqlCreateIndex(Span s, boolean replace) :
{
    final boolean unique;
    final SqlIdentifier indexName;
    final SqlIdentifier table;
    final SqlNodeList columnList;
}
{
    [ <UNIQUE> { unique = true; } | { unique = false; } ]
    <INDEX> indexName = SimpleIdentifier()
    <ON> table = CompoundIdentifier()
    columnList = ParenthesizedSimpleIdentifierList()
    { return new SqlCreateIndex(s.end(this), unique, indexName, table, columnList); }
}

SqlDrop SqlDropIndex(Span s, boolean replace) :
{
    final boolean ifExists;
    final SqlIdentifier indexName;
    final SqlIdentifier table;
}
{
    <INDEX> ifExists = IfExistsOpt() indexName = SimpleIdentifier()
    <ON> table = CompoundIdentifier()
    { return new SqlDropIndex(s.end(this), ifExists, indexName, table); }
}
```

注意事项(已核实):

- `SqlCreate()` 模板对名单里除第一个外的每个 method 注入 `LOOKAHEAD(2)` 前缀——`CREATE ... INDEX` 的 INDEX 首 token 与其它 CREATE 分支无冲突。
- `SqlDrop()` 模板无 LOOKAHEAD 守卫,纯首 token 区分——`INDEX` 首 token 无冲突。
- `<UNIQUE>` 在 `Parser.jj` 模板 9047 行已预声明;`<INDEX>` **未预声明**,必须经 config.fmpp keywords 注入(FMPP 会生成 `<INDEX: "INDEX">` token)。漏了这一步表现是代码生成期报 "INDEX token not declared"。
- `SimpleIdentifier()` / `CompoundIdentifier()` / `ParenthesizedSimpleIdentifierList()` / `IfExistsOpt()` 均为现有辅助。

## Task 4 — DDL 执行(QueryExecutor 分发)

**目标**:`CREATE INDEX`/`DROP INDEX` 走 `QueryExecutor.handleDdl` 分支,完成校验 → 建句柄 → 灌数据 → 落元数据 / 删除句柄 → 去元数据。

### 修改文件

`minidb-server/src/main/java/com/minidb/server/exec/QueryExecutor.java`:

- 顶层解析后 `parsed instanceof SqlDdl` 已经命中(新节点 extends SqlCreate/SqlDrop extends SqlDdl)。`handleDdl` 在 `SqlAlterTable` 分支后、throw 前加:

```java
if (ddl instanceof SqlCreateIndex create) {
    return handleCreateIndex(create, currentSchema);
}
if (ddl instanceof SqlDropIndex drop) {
    return handleDropIndex(drop, currentSchema);
}
```

- `handleCreateIndex(SqlCreateIndex c, String currentSchema)`:
  1. 表名解析:`c.table().names`(ImmutableList)——size>=2 → `[schema, table]`,size==1 → `(currentSchema, name)`(注意:promoted 表名是单段,与坑 17 的解析逻辑一致)
  2. `catalog.getTable(schema, table)` null → `IllegalArgumentException("no such table ...")`
  3. 校验(全失败统一抛 `IllegalArgumentException`,中文/英文消息与现有 DDL 一致):
     - 主键非空(`data.primaryKey().isEmpty()` → "table without primary key cannot have index")
     - 表类型非 SIMPLE:经 `storage.getTable(schema, table)` 取句柄判 `tableType()`;SimpleTable 报错
     - 列存在:`def.columns()` 每列 `data.column(col)` 不抛
     - 列类型 ∈ {SMALLINT, INTEGER, BIGINT, VARCHAR}:其余(DOUBLE/DECIMAL/DATE/TIMESTAMP/BOOLEAN)报错
     - 列未重复:去重后数量一致
     - 索引名表内唯一:`data.indexes()` 无同名(大小写不敏感)
  4. `TableHandle indexTable = storage.indexManager().createIndex(schema, table, def, data)`
  5. `storage.indexManager().populateFromTable(schema, table, def, dataTable, indexTable)`
  6. `catalog.alterTable(schema, table, data.withIndexes(append(def)))`(触发 catalog.json 写盘)
  7. 成败:4/5 抛异常 → catch 内 `indexManager.dropIndex(...)` 清理半成品再 rethrow
  8. 返回 `QueryResult.Update(0)`

- `handleDropIndex(SqlDropIndex d, String currentSchema)`:
  1. 同上解析表名
  2. `data.indexes()` 里按名(大小写不敏感)找 def;找不到 → ifExists 则返回 `QueryResult.Update(0)`,否则抛错
  3. `storage.indexManager().dropIndex(schema, table, name)`
  4. `catalog.alterTable(schema, table, data.withIndexes(去掉该 def))`
  5. 返回 `QueryResult.Update(0)`

## Task 5 — DML 自动维护(MiniDbModify 挂钩)

**目标**:INSERT/UPDATE/DELETE 后索引与数据一致(先写数据后写索引);TRUNCATE 清索引。

### 修改文件

`minidb-server/src/main/java/com/minidb/server/plan/physical/MiniDbModify.java`:

- `appendRows`(INSERT):`validateInsert` 已在写前;写循环里每批 `target.writePart(copy, INSERT)` 后:

```java
if (!target.schema().indexes().isEmpty()) {
    ctx.storage().indexManager().onInsert(target.schema(), copy);
}
```

(copy 是表 schema 列序的批,onInsert 内部按 def 提取下标。)

- `lsmModify`(UPDATE/DELETE):
  - DELETE:`target.writePart(matched, DELETE)` 后 `onDelete(target.schema(), matched)`
  - UPDATE:`target.writePart(out, UPDATE)` 后 `onUpdate(target.schema(), matched, out)`——matched 是旧行批(表 schema 列序),out 是新行批;主键被改时索引也随旧键 tombstone + 新键 insert,天然一致
  - 两分支都先判 `!target.schema().indexes().isEmpty()`
- `rewriteTable`(SimpleTable):建索引已拒绝 SimpleTable,无需挂钩——加一行注释说明即可
- TRUNCATE 的索引清理在 StorageManager.truncateTable(Task 3 已接)

## Task 6 — UNIQUE 索引约束校验(ConstraintChecker)

**目标**:`CREATE UNIQUE INDEX` 生效——INSERT 冲突拒绝;多 NULL 允许;批内多行同键拒绝。

### 修改文件

`minidb-server/src/main/java/com/minidb/server/exec/ConstraintChecker.java`:

`validateInsert(ctx, schema, target, batch)` 在现有主键/唯一键校验后、外键校验前(或后,顺序无所谓)加:

```java
// UNIQUE 索引:含 null 键不参与唯一性(与唯一约束一致);批内同键先自体去重。
for (IndexDef idx : schema.indexes()) {
    if (!idx.unique()) continue;
    TableHandle indexTable = ctx.storage().indexManager()
            .getIndex(schema.schemaName(), schema.name(), idx.name());
    if (indexTable == null) continue;   // 防御:元数据与句柄不同步时跳过
    Set<List<Object>> batchKeys = new HashSet<>();
    for (row : batch) {
        List<Object> key = extractIdxKey(batch, row, idx, schema);  // 索引列值
        if (key contains null) continue;                            // null 键跳过
        if (!batchKeys.add(key)) throw duplicate(...);              // 批内重复
        // 存量重复:索引表前缀点查(己写数据已同步进索引,上一批 commit 即维护)
        if (indexTable.scan(key, key).hasNext()) throw duplicate(...);
    }
}
```

- 错误消息仿现有 unique 冲突文案(如 `Duplicate entry ... for key ...`)
- `scan(List<Object> lo, List<Object> hi)` 全等=前缀点查;注意 scan 是超集语义,但这里 lo==hi==完整前缀,命中即同键唯一(索引表键含主键,同前缀不同主键不可能同索引值组——不,会!`(a)` 索引表键 = (a, pk),scan([v],[v]) 对 key=(v, pk1)与(v, pk2)都算"在前缀内"——这正是我们要的:任意一行的 a=v 即冲突)。✓
- 需要 `getIndex` 已存在(Task 3);`ExecContext` 透传 `storage()` 即可触达(现有 `ctx.storage()`)

### 测试(TDD)
新文件 `minidb-server/src/test/java/com/minidb/server/exec/IndexUniqueTest.java`:

1. 建 `UNIQUE INDEX` 后重复插值抛出异常,affected 不变,数据无残留(半批回滚语义与现有约束一致——看现有唯一约束测试怎么断言)
2. 多行 NULL 索引值允许(插 100 行全 NULL 不报错)
3. 单批内两行同键(单条 INSERT 多行 VALUES)报错
4. 复合 UNIQUE:(a,b) 重复报错,(a 同 b 异)允许
5. UPDATE 改成与已有行冲突 → 报错;改成不冲突 → 成功
6. 建索引时的 populate 对存量重复数据 → CREATE INDEX 抛错(或在 populate 前校验存量唯一性——**先在 populateFromTable 里按批 seen 集校验,冲突即创建失败**;spec 提到 populate 失败删半成品,这里补一点:populate 前用全表行数虚拟校验或直接靠 populate 时分批碰运气——**决策:populate 时不校验**(存量重复由 DBA 自己负责,CREATE UNIQUE INDEX 在 MySQL 也是建失败报 Duplicate entry——更符合直觉)。折衷:populate 完成后**不校验**,但文档注明。选:**populate 前逐批 seen 校验,冲突抛错 + 删半成品**,与 MySQL 行为一致)
